# MemoDolmaeng

평소에는 화면에서 사라져 있다가 엣지에 포인터를 대면 메모 제목만 꺼내 보여주는 로컬 macOS 메모 앱입니다.

## 제품 흐름

- 모든 메모는 소속 엣지 없이 하나의 공용 인덱스 순서를 가집니다.
- 왼쪽이나 오른쪽 엣지 2px에 포인터를 0.18초 대면, 커서 높이를 중심으로 공용 인덱스 트레이가 나타납니다. 상단 엣지는 사용하지 않습니다.
- 포인터가 핫존과 인덱스를 벗어나면 기본 2초 뒤 인덱스가 다시 숨집니다.
- 인덱스 트레이 옆의 `+`를 누르면 트레이를 호출한 엣지에 새 메모가 ICE로 열립니다.
- 좌우 인덱스도 세로 글자가 아닌 26px 높이의 가로형 제목 탭으로 나타납니다.
- 인덱스에 포인터를 올려도 메모는 열리지 않습니다. 클릭하면 곧바로 본문에 입력할 수 있는 `ICE`로 열리고, 같은 ICE 인덱스를 다시 클릭하면 접힙니다.
- ICE를 열면 어느 엣지에서 열렸든 해당 메모가 양쪽 공용 트레이에서 빠지고, 닫으면 저장된 전역 순서로 돌아갑니다.
- 호버 미리보기가 없어서 인덱스 순서 변경이나 휴지통 드래그를 패널이 방해하지 않습니다.
- 각 엣지는 ICE를 최대 3개까지 유지합니다. 새 ICE의 제목 표시줄은 클릭한 인덱스 높이에 남고, 기존 패널은 아래 공간부터 밀린 뒤 부족하면 위쪽으로 재배치됩니다. 네 번째 ICE를 열면 가장 오래된 ICE가 자동으로 원래 인덱스로 돌아갑니다.
- 같은 엣지의 ICE는 같은 높이를 사용하며 화면 안에 모두 들어오도록 필요할 때만 함께 줄어듭니다. 위치는 자동이고 폭만 메모별로 조절·저장합니다.
- `Esc`와 `Cmd+W`는 삭제가 아니라 접기입니다.
- 앱은 Dock 없이 메뉴 막대에 상주하며 모든 Space와 전체 화면 앱 위에서 접근할 수 있습니다.

## 공용 인덱스 트레이

- 메모 수 제한과 활성·보관 구분 없이 모든 메모를 한 인덱스에서 사용합니다.
- 왼쪽과 오른쪽 어디서 호출해도 현재 ICE가 아닌 동일한 메모 목록이 같은 순서로 나타납니다.
- 트레이는 호출 순간의 커서 높이에 고정되며 커서를 계속 따라 움직이지 않습니다.
- 인덱스를 트레이 안에서 드래그하면 전역 순서가 바뀝니다. 메모별 소속 엣지는 없습니다.
- 트레이 밖의 빈 곳에 잘못 놓으면 원래 순서로 돌아오고, 트레이는 정상 표시 상태를 회복합니다.
- 인덱스를 드래그하면 화면 아래 중앙에 삭제 영역이 나타납니다. 그곳에 놓고 확인하면 본문과 첨부파일을 영구 삭제합니다.
- 작은 화면에서는 제목 원본과 툴팁은 유지한 채 인덱스 길이만 자동 압축합니다.
- 제목은 본문과 분리된 전용 입력줄에 최대 40자까지 저장됩니다. 기존 6글자 제목은 본문 첫 줄과 자연스럽게 이어질 때만 전체 표시 제목을 복원하고, 직접 입력한 제목은 그대로 유지합니다.
- 이전 엣지 그룹 데이터는 호환용으로 읽되, 화면에서는 하나의 전역 인덱스 순서로 합쳐 사용합니다.
- 모니터가 사라지면 포인터가 있는 화면, 그다음 주 화면으로 복구됩니다.
- 화면을 고정하지 않은 기본 모드에서는 연결된 모든 모니터의 좌우 핫존을 함께 만들고, 모니터가 분리되면 해당 핫존의 pointer 상태도 즉시 정리합니다.

## 메모 생명주기

- 새 메모는 검정 단일색 대신 노랑, 파랑, 초록, 분홍, 보라, 회색 팔레트에서 무작위 색을 받습니다. 가장 최근 메모와 같은 색은 피해 연속 생성 시 구분력을 높입니다.
- 닫힌 인덱스는 9px, 열린 메모는 10px 모서리 반경을 사용하며 전환 중에는 반경·테두리·제목 정렬도 함께 보간합니다.
- 새 메모는 빈 임시 초안으로 열리며 의미 있는 텍스트, 목록, 표, 코드 또는 이미지가 생긴 순간에만 저장됩니다.
- 빈 초안을 접으면 저장 파일에 흔적을 남기지 않습니다.
- 저장이 실패하면 화면의 최신 본문을 메모리에 유지하고, 다시 저장되거나 저장된 내용으로 되돌리기 전에는 접기·FIFO 교체·앱 종료를 막아 편집 내용을 잃지 않습니다.
- 기존 메모를 완전히 비운 뒤 그 메모를 접거나 앱을 종료하면 본문과 첨부파일을 영구 삭제합니다. 다른 메모를 여는 것만으로는 기존 메모를 닫거나 삭제하지 않습니다.
- 보관함과 자동 보관은 없습니다. 인덱스를 화면 아래 삭제 영역에 끌어놓고 확인했을 때만 영구 삭제합니다.

## 네이티브 편집기

편집기는 AppKit TextKit 2 기반의 `swift-markdown-engine` `0.10.0`을 정확히 고정해 사용합니다. `WKWebView`, Milkdown, Crepe와 npm 빌드 단계는 제거했습니다. Markdown 문자열은 계속 저장 원본이지만, 커서가 서식 밖에 있을 때 `#`, `**`, `~~` 같은 마커를 거의 보이지 않게 줄여 Typora에 가까운 읽기 경험을 제공합니다.

- ICE에서 항상 같은 자리를 유지하는 한 줄 SwiftUI 상단 툴바. 제목·굵게·기울임·목록·이미지는 최소 폭에서도 고정 노출되고, 취소선·인용·코드 도구는 명시적인 더보기 메뉴에 모입니다.
- 툴바와 엣지 인덱스는 hover·pressed·selected 상태와 한국어 접근성 라벨을 제공하며, 조작 영역은 좁은 패널에서도 최소 30pt를 유지합니다.
- TopBar와 본문은 독립된 세로 영역이며, 긴 문서는 TopBar 아래에서만 스크롤됩니다.
- 글머리표, 번호 목록, 체크리스트, 인용, 제목, 구분선, GFM 표
- 굵게, 기울임, 취소선, 인라인 코드와 코드 블록
- `Cmd+B/I`, 실행 취소/다시 실행, 목록 들여쓰기와 한글 조합 입력
- 체크박스 직접 클릭, HTML이 섞인 붙여넣기의 Markdown 변환, macOS 맞춤법·Writing Tools

기본 본문 글꼴은 11pt이며 설정에서 조절할 수 있습니다. 별도 raw Markdown 모드, slash 명령, 블록 드래그 핸들, AI 기능은 제공하지 않습니다. 기존 Markdown 문자열을 임의로 정규화하지 않으므로 지원하지 않는 HTML도 저장 원문에는 남습니다.

이미지는 네이티브 이미지 버튼이나 붙여넣기로 추가합니다. Swift가 실제 이미지 여부와 20MB 제한을 확인한 뒤 `attachments/<note-id>/`로 복사하고, UUID와 단일 파일명만 허용하는 `memodolmaeng-asset://` 경로 해석기로 표시합니다.

## 모션과 접근성

- `EdgeMotionPolicy`가 인덱스, 새 메모 버튼, ICE, 삭제 영역, 콘텐츠 전환의 시간과 접근성 대안을 한곳에서 관리합니다.
- ICE를 펼치고 접는 동안 색상·제목 셸은 계속 보이되, 무거운 TextKit 편집기는 창이 유효한 전체 프레임에 도달한 뒤에만 붙여 레이아웃 흔들림과 본문 팝인을 막습니다.
- Reduce Motion이 켜지면 위치·크기 보간을 사용하지 않고 최종 프레임에서 최대 0.08초의 짧은 fade만 적용합니다.
- Reduce Transparency에서는 커스텀 메모와 인덱스 배경을 불투명하게 표시하고, Increase Contrast에서는 외곽선·구분선·상태 표시를 강화합니다.
- 인덱스와 새 메모 버튼은 VoiceOver press action과 동작 설명을 제공합니다.
- 왼쪽과 오른쪽 트레이를 바꿀 때 기존 창을 화면 반대편으로 순간이동시키지 않고, 이전 엣지를 정리한 뒤 새 엣지 원점에서 나타냅니다.

## 설정과 삭제

- 영구 삭제 확인은 취소가 기본 동작이며 삭제 버튼을 파괴적 행동으로 구분합니다.
- 설정은 메모가 삭제돼도 선택을 자동으로 보정하고, 메모 색상은 32pt 선택 영역과 체크 표시·접근성 선택 상태를 제공합니다.

## 단축키

- `Cmd+Shift+M`: 최근 메모 열기 또는 현재 메모 접기, 시스템 전역
- `Cmd+Shift+Up`, `Cmd+Shift+Down`: 열린 상태에서 이전 또는 다음 메모
- `Cmd+1`~`Cmd+0`: 열린 상태에서 1~10번 메모로 전환
- `Esc`, `Cmd+W`: 현재 메모 접기
- `Cmd+N`: 새 임시 메모

전역 단축키는 Carbon Hot Key API를 사용하므로 접근성 권한이 필요하지 않습니다.

## 로컬 저장과 v5 이전

```text
~/Library/Application Support/MemoDolmaeng/
├── notes.json
├── Backups/
├── attachments/<note-id>/
└── DeletionStaging/
```

```json
{
  "schemaVersion": 5,
  "notes": [],
  "edgeGroups": [],
  "defaultGroupID": "UUID"
}
```

`panelSize.width`는 사용자가 직접 조절한 ICE 폭을 보존합니다. 높이와 위치, 열린 ICE 상태는 저장하지 않으며 앱을 다시 열면 전부 인덱스로 시작합니다.

v4를 처음 열 때 원본을 `Backups/notes-pre-no-library-v5-<timestamp>.json`에 백업한 뒤, 과거 `isActive` 상태를 제거하고 모든 메모를 공용 인덱스에 합칩니다. 메모 ID·제목·본문·첨부·순서·저장 폭은 유지합니다.

v3를 처음 열 때 원본을 `Backups/notes-pre-edge-stack-v5-<timestamp>.json`에 백업한 뒤 여러 자유 그룹을 엣지별 한 그룹으로 평탄화합니다. v2를 처음 열 때는 원본 바이트를 `Backups/notes-pre-edge-v3-<timestamp>.json`에 먼저 기록합니다. 내용이 있는 메모만 가져오며 백업, 변환 또는 v5 저장이 실패하면 원본을 바꾸지 않고 앱 시작을 중단합니다.

첨부파일 영구 삭제는 디렉터리를 staging으로 이동한 뒤 메모 저장에 성공하면 물리 삭제합니다. 중간에 앱이 종료되면 다음 시작 때 메모 존재 여부에 따라 복구하거나 정리합니다.

## 구조

- `EdgeWorkspaceController`: 공용 인덱스 순서, 좌우 호출 엣지, 초안/삭제 생명주기와 엣지별 3개 ICE 큐
- `EdgeLayoutEngine`: 커서 기준 공용 트레이와 최신 클릭 위치 기준 무중첩 ICE 프레임 계산
- `EdgeMotionPolicy`: 일반 모션과 Reduce Motion·Transparency·Increase Contrast의 공통 정책
- `EdgeHotZoneController`, `EdgeHandlePanelController`, `EdgeControlPanelController`: 숨김 핫존, 인덱스와 엣지 `+` 패널
- `DeleteDropZoneController`: 인덱스를 끌 때만 나타나는 영구 삭제 드롭 영역
- `MemoPanelController`, `UnifiedEdgeMemoSurfaceView`: 클릭 기준 자동 위치·스택 공통 높이·가변 폭을 적용하는 메모별 독립 네이티브 표면
- `MarkdownEditorView`: TextKit 2 편집기, 네이티브 TopBar와 Markdown 명령 버스
- `NoteStore`: v5 저장, 이전 버전 안전 백업·평탄화와 무제한 전역 인덱스 순서
- `AttachmentService`, `MemoAssetSchemeHandler`: 이미지 복사, staged 삭제, 안전한 로딩
- `PreferencesView`: 공통/메모별 설정

## 실행과 검증

```bash
swift test
swift build
./script/build_and_run.sh --verify
```

검증 스크립트는 로컬 앱 번들을 조립한 뒤 ad-hoc 서명과 무결성 검증을 먼저 통과시킨 다음 실행합니다. 외부 배포용 Developer ID 서명과 notarization은 별도 릴리스 단계입니다.

격리 저장소 실행:

```bash
MEMODOLMAENG_DATA_DIR=/tmp/memodolmaeng-qa \
  ./dist/MemoDolmaeng.app/Contents/MacOS/MemoDolmaeng
```
